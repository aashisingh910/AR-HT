# HomeTown AR — project guide for Claude

One React Native (Expo dev build) app that lets people place true-to-size HomeTown furniture in their room with AR,
plan rooms, get suggestions, and save/share designs. It is being built by **merging two prototypes**:

- **This folder (root)** = "HomeTown Room Designer" (HTRD). It is the BASE. Keep its code unless a step says otherwise.
- **`reference/furniar/`** = "FurniAR". Read-only SOURCE to port features from. Never import from it at runtime;
  copy/adapt code into `src/`, `server/`, `scripts/`. It will be deleted at the end.

The build is done in numbered steps in `prompts/`. Do one step per session. Do not start the next step's work.

## Commands
```bash
npm install
npm run typecheck        # tsc --noEmit — must pass
npm test                 # node unit tests in scripts/*.test.ts — must pass
npm run validate:models  # GLB size vs listed size
npm run doctor           # expo-doctor
cd server && npm install && npm test   # API tests — must pass
npx expo prebuild && npx expo run:android   # needs a real ARCore phone (AR cannot run in emulators / Expo Go)
```

## Stack
Expo SDK ~57, React Native 0.86, React 19, TypeScript strict, React Navigation 7, Zustand 5 (+persist),
@reactvision/react-viro 3.0.2 (ARKit/ARCore), react-native-webview + bundled @google/model-viewer for 3D preview.
Server: Node 22, Express 5, zod, JWT, bcryptjs, multer, @gltf-transform. (SQLite now; Postgres in step 09.)

## Conventions that must never break
- **Units:** product data in centimetres (`dimensionsCm: {w, d, h}`), AR world in metres.
- **Model frame:** every GLB / proxy has origin at the centre of its floor footprint, base on y=0, **front faces +z**,
  w along x, d along z. Collision, placement, validators and layouts all assume this.
- **Rotation:** `rotationY` in degrees about +Y, Viro right-handed convention (local +x → (cos a, 0, −sin a)).
- **Saved designs store offsets**, never raw world positions (AR world origin changes every session). Three modes:
  offset from first piece; two-point frame (`utils/frame.ts`); cloud-anchor pose.
- **True scale is sacred:** resize is clamped to 80–125%. Proxies are stretched to the real W×H×D.
- **Camera frames never leave the phone**, with two exceptions: (1) a design's thumbnail (a screenshot of the AR view) is uploaded only when the user shares that
  design or turns on "Back up design photos" (off by default); (2) "Redesign my room" (room AI, `src/screens/RoomRedesignScreen.tsx` ->
  `/v1/room-ai` -> `server/ml-service`) sends the ONE photo the user picks, after an explicit consent switch, shrunk to 1024 px with EXIF removed.
  The server deletes it as soon as the ml-service has read it and deletes the results when the user leaves the screen (or after 1 h).
  AR camera frames are never sent. Analytics events carry ids and numbers only.
- **AR library isolation:** only files under `src/ar/` may import `@reactvision/react-viro` (from step 01 on).
- **No checkout, but prices everywhere.** Every product card/page shows its HomeTown price (`PriceTag`, with sale discount), and
  every group of pieces (design, sample room, wishlist, shared page, AR, plan, studio) shows an estimated total (`Estimate` /
  `budgetOf`, sets counted once). Both live in `src/components/Price.tsx`; `SHOW_PRICES=0` remains only as an emergency off switch.

## Code rules
- TypeScript strict, no `any` in new code unless wrapping Viro events. Small files: a screen file over ~300 lines
  gets split into components/hooks.
- Pure logic (geometry, room maths, recommendations, sync) lives in `src/utils`, `src/recommend`, `src/sync` with
  NO React/Viro imports, and gets a test in `scripts/*.test.ts` (run with `node --experimental-strip-types`).
- Every server route: zod-validated input, owner checks, a test in `server/test/`.
- UI uses `src/theme.ts` colours and `src/components/ui.tsx` primitives. Every pressable has an accessibilityLabel.
- Secrets never in the app bundle. `EXPO_PUBLIC_*` env vars are public.
- Before finishing any step: run typecheck + `npm test` + server tests, fix failures, then summarise what changed and
  what must be checked on a real phone. Commit with a message `step NN: <summary>`.

## Known facts about the data
- Source is HomeTown's Shopify export `HT_Data_dump.csv` (not in repo; 40,856 rows, 5,505 products). Sizes are messy:
  units mixed, length/width/depth labels swapped, bed heights in the wrong column. Never trust a size without the
  plausibility checks; flagged items get `sizeReview` and are not placeable.
- No product has a real 3D model yet. Placeable items use proxy shapes. 4 Khronos demo GLBs are flagged `demo: true`.
